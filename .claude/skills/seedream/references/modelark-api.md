## Authentication and endpoint

- Set `ARK_API_KEY` and send it as a bearer token.
- In agent workflows, if the key is missing, ask the user to provide it, then run `export ARK_API_KEY="..."` in the active shell session before invoking the script.
- Use the ModelArk data-plane base URL:
  `https://ark.ap-southeast.bytepluses.com/api/v3`
- The image endpoint is:
  `POST /images/generations`
- The OpenAI-compatible Python pattern shown in the official quick start is:
  `client = OpenAI(base_url="https://ark.ap-southeast.bytepluses.com/api/v3", api_key=os.getenv("ARK_API_KEY"))`

## Model/version notes

- The BytePlus quick start uses `seedream-5-0-260128` for image generation.
- The Seedream 4.0 model page documents `seedream-4-0-250828`.
- The model list describes Seedream 5.0 as the leading image generation model and highlights stronger reference consistency.
- The Seedream 4.0 model page documents support for text input, single-image input, and multi-image input, plus image-set generation with `sequential_image_generation`.
- Do not assume these IDs stay stable. If the user asks for the latest production model, re-check the docs above before invoking.

## Prompt enhancement recommendations

What the official docs recommend:

- Seedream 4.0 and 4.5 prompt guides recommend coherent natural language with a clear scene description: subject + action + environment.
- The same guide explicitly recommends specifying the application scenario when relevant, such as poster, logo, infographic, UI, or product render.
- For text that must appear in the image, the guide recommends wrapping the exact text in double quotation marks.
- For editing, the guide recommends direct, unambiguous instructions plus explicit preservation constraints such as pose, composition, or unchanged elements.
- For multi-image tasks, the guide recommends clearly stating what each input image contributes.
- The Seedream 3.0 prompt guide says short prompts can work very well and notes that prompts generated by AI are not automatically better than concise prompts written by the user.

What this means for the skill:

- Treat prompt enhancement as prompt clarification, not prompt inflation.
- Prefer converting a rough brief into a concise, concrete prompt instead of adding piles of style adjectives.
- Use enhancement most when the user brief is underspecified, ambiguous, or missing output-type and preservation constraints.
- Do not “enhance” an already-good prompt unless the user asks for optimization.
- Do the rewrite inside the agent workflow. Do not call a separate optimization model unless the user explicitly asks for that architecture.

Practical rewrite pattern:

- Start from the user brief.
- Add missing pieces in this order: output type, subject, action, setting, composition, lighting, style, text-in-image, and preservation constraints.
- Stop once the prompt is concrete enough to control the result.

Example:

- Raw brief: `summer coffee poster`
- Better prompt: `Design a premium but approachable summer coffee poster for a cafe. Show a clear plastic cup of iced cold brew with visible condensation on a sunlit outdoor table, warm late-afternoon light, crisp commercial photography, clean layout, and the headline "Summer Cold Brew".`

## Request shape

Common documented fields across the quick start, Seedream tutorial pages, and related image-generation tutorials:

- `model`: Model ID such as `seedream-5-0-260128`
- `prompt`: Natural-language instruction
- `image`: Optional reference image input. For multi-image workflows, pass multiple images in the shape expected by the current API docs.
- `size`: Accepts shorthand `"2K"` (2048×2048) and `"3K"` (3072×3072), **and** explicit `"<W>x<H>"` strings (e.g. `"1440x2560"`, `"2560x1440"`, `"1920x2560"`). Constraint: total pixels `W*H >= 3,686,400`. Aliases `"1K"`, `"512x512"`, and `"adaptive"` are rejected by Seedream 5.x — do not use them. Pick the aspect by asset role (see the asset-role table in `SKILL.md`), not by defaulting to 2K.
- `response_format`: Use `url`. This skill standardizes on URL responses and surfaces the returned image links directly.
- `watermark`: Boolean
- `seed`: Optional, shown in SeedEdit examples
- `guidance_scale`: Optional, shown in SeedEdit examples
- `sequential_image_generation`: `auto` for image sets and `disabled` for single-image generation on Seedream 4.0

Conservative rule:

- If a parameter is not clearly needed, omit it.
- If the task is plain text-to-image, start with `model`, `prompt`, `size`, `response_format=url`, and `watermark`.
- Add `image` only for editing, reference-based generation, or multi-image composition.

## Common invocation patterns

Text-to-image via curl:

```bash
curl https://ark.ap-southeast.bytepluses.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "seedream-5-0-260128",
    "prompt": "Vibrant close-up editorial portrait, sculptural hat, dramatic studio lighting.",
    "size": "2K",
    "response_format": "url",
    "watermark": false
  }'
```

OpenAI-compatible Python example:

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://ark.ap-southeast.bytepluses.com/api/v3",
    api_key=os.getenv("ARK_API_KEY"),
)

images = client.images.generate(
    model="seedream-5-0-260128",
    prompt="Vibrant close-up editorial portrait, sculptural hat, dramatic studio lighting.",
    size="2K",
    response_format="url",
    extra_body={"watermark": False},
)

print(images.data[0].url)
```

CLI flow used by this skill:

```bash
export ARK_API_KEY="..."
python3 scripts/seedream.py \
  --model seedream-5-0-260128 \
  --prompt "Your prompt here" \
  --size 2K \
  --response-format url \
  --no-watermark \
  --output-dir out/run-name
```

Image editing or reference generation:

- Provide one or more reference images.
- Tell the model exactly what to change.
- State what must remain fixed: pose, composition, branding, product material, camera angle, or style.

Image-set generation:

- Use `sequential_image_generation=auto`.
- Seedream 4.0 docs describe text-to-set, single-image-to-set, and multi-image-to-set generation.
- The Seedream 4.0 page states the total of input reference images plus generated images must be `<= 15`.

## Prompting guidance

The official Seedream prompt guide recommends:

- Describe the scene in coherent natural language.
- Specify the application scenario when it matters, such as poster, logo, UI, product render, or storyboard.
- Use precise style descriptors instead of vague adjectives.
- Wrap text that must appear in the image in double quotation marks.
- For editing, use direct instructions and explicitly preserve fixed elements.
- For multi-image tasks, identify each image by role, for example: "Use Image 1 as the background, replace the subject in Image 2 with the character from Image 3."

Practical guidance for agents:

- Prefer concise but concrete prompts on Seedream 4.x and 5.x.
- Do not pile on decorative adjectives unless the user explicitly wants maximal style steering.
- If the user provides a rough idea only, turn it into: subject + action + setting + composition + lighting + style + output type.

## Output handling

- This skill uses `response_format=url`.
- Store the returned JSON and surface each concrete `data[*].url` value to the user.
- If local files are needed, download each URL after generation.
- Keep the full raw response if the result may be audited, retried, or reused downstream.
